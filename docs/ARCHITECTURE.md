# معماری و امنیت

## مسیر تصمیم و مصرف

مرورگر ← Nginx/HTTPS یا تونل SSH ← Gunicorn/Flask ← SQLite ← Agent ← سوکت Unix مدیریتی OpenVPN.

OpenVPN کانال `management-client-auth` را برای تأیید اتصال استفاده می‌کند. Agent رویدادهای `CONNECT/REAUTH` را بررسی می‌کند و فقط CID/KID عددی را در فرمان پاسخ استفاده می‌کند؛ نام و رمز کاربر وارد فرمان مدیریت یا shell نمی‌شوند. حساب باید فعال، دارای زمان و حجم باقی‌مانده و ظرفیت اتصال باشد. نشست‌های در حال تأیید هم ظرفیت مصرف می‌کنند تا اتصال‌های هم‌زمان از سقف عبور نکنند.

`BYTECOUNT_CLI` شمارنده تجمعی نشست است. در تراکنش SQLite تنها افزایش مثبت ثبت می‌شود. `DISCONNECT` شمارنده نهایی را ثبت می‌کند؛ تکرار پیام موجب مصرف تکراری نمی‌شود. هر بار استفاده مجدد از CID، شناسه نشست جدید ساخته می‌شود. اتصال مجدد Agent نشست‌های قدیمی را خاتمه‌یافته علامت می‌زند؛ مصرف حفظ می‌شود. پنل و Agent روی یک دیتابیس WAL با تراکنش `BEGIN IMMEDIATE` کار می‌کنند.

## خرابی و قطع دسترسی

Agent هر ثانیه وضعیت حساب‌ها را بررسی و با `client-kill` نشست را قطع می‌کند. کاهش سقف اتصال، تغییر رمز یا قطع دستی باعث درخواست قطع نشست‌ها می‌شود. Agent هر پنج ثانیه از OpenVPN پاسخ زنده می‌خواهد؛ عدم پاسخ به فرمان پس از ده ثانیه باعث بستن سوکت می‌شود. `management-signal` روی سرور، قطع سوکت را به بازنشانی OpenVPN تبدیل می‌کند. `management-hold` شروع اولیه را تا اتصال Agent نگه می‌دارد. systemd watchdog هنگ Agent را با تأخیر حداکثر حدود ۳۰ ثانیه تشخیص می‌دهد؛ توقف سخت فوراً سوکت را می‌بندد.

این‌ها تضمین صددرصد بدون اتلاف یا بدون عبور اضافه از سهمیه نیستند. تست رفتار واقعی daemon/kernel در `ACCEPTANCE.md` الزامی است. خرابی دیتابیس باید باعث خروج Agent و بسته‌شدن رابط مدیریت شود، نه ادامه تأیید حساب‌ها.

## مرزهای دسترسی

- وب و Agent با حساب سیستمی `datisvpn` و بدون sudo اجرا می‌شوند؛ نیازی به اجرای shell از درخواست وب ندارند.
- وب و Agent یک مرز اعتماد دارند: به دیتابیس و حساب datisvpn اعتماد می‌شود. جداسازی آن‌ها در حد کاربر سیستم‌عامل پیاده‌سازی نشده؛ نفوذ به یکی می‌تواند داده/کنترل دیگری را تحت تأثیر قرار دهد.
- OpenVPN ابتدا برای TUN/route با root اجرا می‌شود، سپس به nobody/nogroup تغییر هویت می‌دهد.
- CA و کلید خصوصی سرور root-only هستند. وب صرفاً پروفایل آماده و گواهی عمومی را می‌خواند.
- سوکت مدیریت عمومی TCP وجود ندارد؛ Unix socket فقط کاربر و گروه datisvpn را می‌پذیرد.
- کد و virtualenv متعلق به root هستند. سرویس‌ها نمی‌توانند کد نصب را بازنویسی کنند.
- ورود وب دارای هش scrypt، نشست تصادفی ذخیره‌شده به شکل هش، CSRF، کوکی HttpOnly/SameSite و در HTTPS کوکی Secure است. اعتبار نشست حداکثر ۸ ساعت است؛ تغییر رمز نشست‌های قبلی را باطل می‌کند.
- پشت Nginx، محدودیت تلاش IP عمداً برای همه درخواست‌های proxy مشترک است؛ به X-Forwarded-For کاربر اعتماد نمی‌شود. محدودیت نام کاربری هم اعمال می‌شود. این می‌تواند در حمله باعث محدودشدن موقت ورود مدیر شود؛ دسترسی SSH برای بازیابی مستقل باقی می‌ماند.
- فایل‌های پشتیبان شامل هش رمزها، IPها و اطلاعات حساب‌ها هستند؛ آن‌ها را خصوصی و ترجیحاً رمزگذاری‌شده نگه دارید. سوکت/لاگ مدیریت خام را منتشر نکنید: اطلاعات احراز هویت دارد.
- پیش‌فرض VPN اینترنت IPv4 است. کلاینت به مسدودسازی IPv6 هدایت می‌شود و سرور forwarding از رابط VPN در IPv6 را Drop می‌کند. آزمون نشت DNS/IPv6 روی هر برنامه کلاینت جداگانه لازم است.
- ارتباط کاربران با یکدیگر و سرویس‌های روی خود سرور مسدود می‌شود. مسیرهای خصوصی IPv4 و metadata لینک‌محلی نیز مسدود می‌شوند.

## دامنه نسخه ۰.۱

این پروژه جایگزین اکانتینگ مالی دارای SLA نیست. مقیاس/کارایی تحت صدها اتصال بنچمارک نشده، MFA و API عمومی و چندنودی ندارد. اکانت‌ها با username/password و CA سرور اعتبارسنجی می‌شوند؛ گواهی اختصاصی کاربر و CRL لازم ندارند. لغو دسترسی با وضعیت حساب اعمال می‌شود.
